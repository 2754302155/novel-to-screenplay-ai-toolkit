YAML 剧本初稿字段说明

这份文档面向小说作者和编剧编辑，帮助你读懂 AI 生成的 YAML 剧本初稿。YAML 不是最终成片剧本， 而是一份结构化创作底稿：它把小说章节拆成项目资料、改编方向、人物表、场景、节拍和质量提示，方便后续继续改写。

先看主线 adaptation 概括改编方向，scenes 承载具体戏。
再查来源 source_refs 会标出场景来自哪些章节，便于回到原文核对。
最后复核 quality_report 会列出需要人工确认的问题和风险。

1. YAML 怎么读

YAML 用缩进表达层级。冒号左边是字段名，右边是内容；以短横线开头的多行内容表示数组，例如多个角色、多个场景或多个节拍。 

characters:
  - id: CHAR001
    name: 许七安
    role_type: protagonist
scenes:
  - id: SCENE001
    source_refs: [CH001]
    beats:
      - type: action
        text: 许七安在牢房中醒来，意识到处境异常。
编辑时请尽量保留字段名和缩进，只修改字段值。数组字段没有内容时写成 []，不要改成 false、无 或空白。

2. 顶层结构总览

字段 作用 作者需要关注什么
schema_version 标记当前 YAML 结构版本。 通常保持为 "1.0"，用于系统校验和后续兼容。
project 记录作品标题、作者和生成时间。 可把标题改成正式剧名，把作者补全为原作者或改编者。
source 记录本次转换使用的章节范围。 用来确认是否选中了正确章节，以及后续每场戏是否有来源依据。
adaptation 记录改编格式、故事钩子、梗概和主题。 这是给编剧快速理解故事方向的摘要，可以大胆精修。
characters 人物表，供场景引用。 重点核对姓名、别名、身份、首次出场章节是否正确。
scenes 剧本初稿的核心，按场景组织动作、对白、旁白和转场。 后续改写主要围绕这里展开：增删场景、调整节奏、补对白。
continuity 可选字段，记录跨章节连续性。 适合长篇小说分批转换时保存伏笔、时间线和待解决问题。
quality_report 质量报告，记录覆盖率、警告和人工复核项。 转换后先看这里，可以快速发现 AI 推断或遗漏的地方。

3. 项目信息：project

project.title 作品或项目名称。AI 不确定时可能写“未命名作品”。
project.author 作者或改编者。可以填写小说作者、编剧团队或项目负责人。
project.generated_at 生成时间，便于区分不同版本。通常不需要手动修改。

4. 来源章节：source

source 不是正文，而是本次转换范围的索引。章节正文不会写入 YAML，避免结果文件过长，也便于保护原文内容。

source.chapter_count 本次参与转换的章节数量。
source.chapters[].id 章节编号，例如 CH008。场景里的 source_refs 会引用它。
source.chapters[].title 章节标题，用于作者快速定位原文。
source.chapters[].word_count 章节字数估算，可辅助判断某章是否被过度压缩或遗漏。

5. 改编方向：adaptation

adaptation.format 目标形态，例如短剧、网剧、电影分场或创作素材。
adaptation.logline 一句话故事钩子，用来说明主角、目标、冲突和看点。
adaptation.synopsis 本次章节范围的剧情梗概。适合给导演、制片或编剧快速同步。
adaptation.themes 主题数组，例如权谋、成长、复仇、悬疑。没有明确主题时写 []。

6. 人物表：characters

人物表为场景服务。每个场景的 characters 字段应该引用这里的 id，这样系统和作者都能知道场景里有哪些人。

characters[].id 人物唯一编号，例如 CHAR001。修改编号时，要同步修改场景引用。
characters[].name 人物姓名。若 AI 写成“待确认角色”，需要回到原文核对。
characters[].aliases 别名、称号、外号数组，例如官职、江湖名、化名。
characters[].role_type 人物功能，例如 protagonist、antagonist、supporting、unknown。
characters[].description 人物身份、动机、关系和当前状态的简述。
characters[].first_appearance 首次出场章节编号。用于追踪人物进入故事的时间点。

7. 场景：scenes

scenes 是最重要的部分。它把小说叙事转换成可继续编辑的剧本场面。每个场景至少有一个节拍， 节拍可以是动作、对白、旁白、转场或备注。

scenes[].id 场景编号，例如 SCENE001。用于排序和后续引用。
scenes[].source_refs 来源章节数组，例如 [CH008]。一个场景跨多章时可写多个。
scenes[].heading 场景标题，通常包含内外景、地点、时间，例如“内景 - 驿站客房 - 夜”。
scenes[].location 具体地点。若 AI 不确定，可以先写“待确认地点”，后续再改。
scenes[].time_of_day 时间段，例如夜、清晨、白天、unknown。用于拍摄和氛围判断。
scenes[].characters 场景出场人物 ID 数组，必须对应 characters[].id。
scenes[].dramatic_purpose 这场戏的戏剧功能，例如揭示秘密、制造冲突、推动主角做选择。
scenes[].beats 场景内部的节拍列表，是动作、对白和转场的具体内容。
scenes[].notes 编辑备注数组，记录需要补充的信息或改写建议。

节拍 beats 的字段

beats[].type 只能使用 action、dialogue、voice_over、transition、note。
beats[].speaker 对白或旁白的说话人。动作和转场可留空字符串 ""。
beats[].text 具体内容，不能留空，也不要写“待补充”。这是后续改写的主要材料。
beats[].confidence AI 对该节拍的把握程度，范围是 0 到 1。数值低时建议回原文核对。

8. 连续性：continuity

continuity 是可选字段，特别适合长篇小说分批转换。它帮助后面的章节延续前面的时间线、伏笔和未解决问题。

continuity.timeline 时间线关键节点，例如“主角醒来”“案件线索出现”。
continuity.foreshadowing 伏笔数组，记录后续需要回收的信息。
continuity.unresolved_issues 尚未解决的问题，例如人物动机不明、线索未解释。
continuity.carry_forward_notes 需要带到下一批章节继续使用的设定和编辑提醒。

9. 质量报告：quality_report

coverage.converted_chapters 已覆盖章节数量。应接近本次选择章节数。
coverage.estimated_unconverted_ratio 估算未转换比例，0 表示没有明显遗漏，数值越高越需要复核。
warnings 警告数组，记录 AI 推断、结构不确定、内容偏保守等风险。
human_review_required 人工复核项数组。这里列出的事项建议作者优先处理。

10. 作者编辑建议

  1. 先确认 source.chapters 是否是你想转换的章节范围。
  2. 阅读 adaptation.logline 和 synopsis，判断 AI 是否抓住故事核心。
  3. 核对 characters，尤其是姓名、别名、身份和人物关系。
  4. 逐场检查 scenes[].source_refs，确保场景来源没有错章。
  5. 把低置信度 confidence 或含“待确认”的内容回原文核对。
  6. 根据 quality_report.human_review_required 逐条补齐人工判断。
  7. 保存前使用页面里的“重新校验”，确认 YAML 结构仍然有效。

11. 小型参考模板

schema_version: "1.0"
project:
  title: 示例作品
  author: 作者名
  generated_at: "2026-06-06T00:00:00Z"
source:
  chapter_count: 3
  chapters:
    - id: CH001
      title: 第一章
      word_count: 3200
adaptation:
  format: web_drama
  logline: 主角在危机中发现隐藏身份，被迫卷入更大的阴谋。
  synopsis: 本段章节建立主角困境、关键线索和第一轮冲突。
  themes: [身份错位, 悬疑, 成长]
characters:
  - id: CHAR001
    name: 主角
    aliases: []
    role_type: protagonist
    description: 被卷入事件的核心人物，目标是活下去并查明真相。
    first_appearance: CH001
scenes:
  - id: SCENE001
    source_refs: [CH001]
    heading: 内景 - 房间 - 夜
    location: 房间
    time_of_day: 夜
    characters: [CHAR001]
    dramatic_purpose: 建立主角危机和第一条线索。
    beats:
      - type: action
        speaker: ""
        text: 主角醒来，发现环境陌生，门外传来急促脚步声。
        confidence: 0.82
    notes: []
quality_report:
  coverage:
    converted_chapters: 3
    estimated_unconverted_ratio: 0
  warnings: []
  human_review_required: []
